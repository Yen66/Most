# Принятые допущения

## 2026-09-21 — имя объекта в ВОР отсутствует
**Вопрос:** как назвать объект при импорте ВОР, если обезличенная ведомость не содержит однозначного имени объекта?  
**Варианты:** выдумать имя; требовать новый CLI-параметр; использовать имя файла как технический идентификатор.  
**Что выбрано:** использовать stem имени файла (`vor_object_a`) как техническое имя.  
**Почему:** это не выдумывает предметные данные и не расширяет обязательный интерфейс импорта.  
**Что переделывать, если неверно:** добавить явное поле/параметр имени объекта и миграцию существующих технических имён.

## 2026-09-21 — тип договора отсутствует
**Вопрос:** какой тип договора сохранять, если в импортируемой ведомости он не определяется?  
**Варианты:** считать государственным; считать коммерческим; сохранить `unknown`.  
**Что выбрано:** `unknown`.  
**Почему:** запрещено придумывать отсутствующие данные.  
**Что переделывать, если неверно:** заменить значение после получения договора через отдельную подтверждённую операцию.

## 2026-09-21 — повторный импорт того же SHA-256
**Вопрос:** создавать новую версию или пропускать идентичный файл?  
**Варианты:** supersede; пропуск.  
**Что выбрано:** пропуск.  
**Почему:** бинарный источник не изменился; создание новой версии без новых данных породило бы дубликаты.  
**Что переделывать, если неверно:** ввести версию интерпретатора и `supersede` с причиной `reimport`.


## 2026-09-20 — заполнение valid_from миграции 0002
**Что выбрано:** литерал `2026-09-20`, после backfill server default снимается.  
**Почему:** SQLite не допускает непостоянный default при ADD COLUMN; приложение после миграции обязано передавать дату.  
**Что переделывать, если неверно:** отдельной корректирующей миграцией заменить даты подтверждёнными источниками.

## 2026-09-20 — состояние данных при миграции 0002
На момент проектирования миграции реальных строк в `contracts`, `objects`, `schedule_tasks` в целевой базе не было; литерал нужен для воспроизводимого upgrade с нуля.

## 2026-09-23 — неизвестный способ актирования
**Вопрос:** как выбрать срок оплаты при `via_eis=NULL`?  
**Варианты:** остановка; считать без ЕИС; считать ЕИС с предупреждением.  
**Выбор:** ЕИС (7 рабочих дней) с предупреждением «via_eis: нет данных — принято ЕИС-актирование».  
**Почему:** детерминированное правило задания, без скрытого предположения.  
**Что переделывать:** при получении факта сделать supersede акта и обязательства.

## 2026-09-23 — договорной срок и оплата v1
**Вопрос:** как интерпретировать `payment_delay_days` и частичные платежи?  
**Варианты:** календарные/рабочие дни; несколько платежей/одно событие.  
**Выбор:** рабочие дни; при >10 — предупреждение о 44-ФЗ; одно платёжное событие на версию обязательства.  
**Почему:** ограничения этапа и явный приоритет договора.  
**Что переделывать:** график платежей задачи 13, проверка договорного режима.

## 2026-09-23 — календарь и региональные исключения
**Вопрос:** учитывать региональные праздники и даты вне покрытия?  
**Варианты:** эвристика по выходным; федеральный календарь с ошибкой вне 2026–2027.  
**Выбор:** только федеральный календарь, отсутствие даты → «нет данных».  
**Почему:** регион и режим сменности для объекта неизвестны.  
**Что переделывать:** отдельные календари регионов/объектов и сид 2028+.

## 2026-09-23 — договорной потолок пени
**Вопрос:** применять нормативный лимит при незаполненном `penalty_cap_pct`?  
**Варианты:** выдуманный потолок; отсутствие потолка с предупреждением.  
**Выбор:** без потолка; предупреждение о ст. 333 ГК РФ.  
**Почему:** 44-ФЗ не задаёт нормативный потолок пени заказчика.  
**Что переделывать:** при получении условия договора supersede договора.
