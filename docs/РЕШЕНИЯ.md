# Реестр решений

- 2026-09-21 — деньги и денежные округления только через `Decimal`/`ROUND_HALF_UP`.
- 2026-09-21 — нормативные ставки датированы и получаются через `get_rate`; литералы ставок вне `references/` запрещены тестом AST.
- 2026-09-21 — реальные документы не хранятся в Git; разрешены только обезличенные XLSX в `tests/fixtures/`.
- 2026-09-21 — повторный импорт того же SHA-256 идемпотентно пропускается.
- 2026-09-21 — `company_id` закладывается в tenant-таблицы без реализации SaaS/ролей/биллинга.
- 2026-09-21 — предметный `domain/` не зависит от SQLAlchemy.
- 2026-09-21 — себестоимость, прибыль, cash-flow и прочие следующие модули сознательно не реализуются в фундаменте.

## 23.09.2026 — задачи 9–12
- `egg-info` исключён из индекса и игнорируется.
- Федеральный календарь 2026–2027 глобальный, без `company_id`; даты вне покрытия не угадываем.
- Акты и обязательства версионируются; отказ сбрасывает срок при повторном размещении.
- Пени считаются из обязательств и датированного KEY_RATE, без таблицы начислений.
- Потолок только из договора; история ставок справочная, не периодная формула.

## 23.09.2026 — задача 13
- ADR-0015: кассовый разрыв — отрицательный остаток на конец календарного дня; финансирование [ОЦЕНКА] по одной датированной ставке; build идемпотентен по версии обязательства.
- ADR-0016: what-if не пишет в БД, использует ядро scenarios; обратный счёт замкнутый, остаток округления не скрывается.
- Задержка графика `schedule_shift_days` отложена до отдельной задачи: существующее ядро параметр не потребляет.
